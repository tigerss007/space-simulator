# 프로젝트: 복합개발 상업시설 배치·호실 등급 3D 시뮬레이터

## 0. 작업 방식 (먼저 읽기)
- 이 문서 전체를 `docs/SPEC.md`로 저장하고, 핵심 규칙만 요약해서 `CLAUDE.md`를 만든다.
- 아래 "개발 단계"를 Phase 순서대로 진행한다. Phase 하나가 끝날 때마다 실행 방법과 확인할 것을 알려주고, 사용자가 확인한 다음에 다음 Phase로 넘어간다.
- Phase가 끝날 때마다 git 커밋한다. 커밋 메시지는 한국어로.
- UI 문구, 주석, 안내 메시지는 모두 한국어로 쓴다.
- 그래프 알고리즘(최단경로, 통합도, 선택도)에는 반드시 단위 테스트를 붙인다. 작은 예제 그래프로 손으로 계산한 값과 비교한다.
- 공개 범위: 링크만 있으면 누구나 쓸 수 있는 공유용 도구.
  - 서버나 DB 없이 브라우저만으로 돌아가는 정적 웹사이트로 만든다.
  - Phase 1부터 GitHub Pages 자동 배포(GitHub Actions)를 설정해서, main 브랜치에 올라가면 공유 링크가 바로 갱신되게 한다. Vite의 base 경로도 저장소 이름에 맞춘다.
  - 개발 중에는 `npm run dev`로 로컬에서 먼저 확인할 수 있어야 한다.
- 데이터 보호: 사용자가 입력한 프로젝트 데이터는 그 사람의 브라우저와 직접 저장한 JSON 파일에만 있어야 한다. 외부로 데이터를 보내는 기능(분석 도구, 외부 API 호출)은 넣지 않는다. 화면 하단에 "입력한 데이터는 서버로 전송되지 않습니다"라고 안내한다.
- 처음 들어온 사람도 쓸 수 있게 첫 화면에 샘플 프로젝트와 간단한 사용 안내(3단계 정도)를 보여준다.

## 1. 목적
복합개발사업을 검토할 때 건물 형상(층·호실·복도·수직동선)과 주변 여건(배후세대·근접상권·대형유통·역 출구)을 입력하면 아래를 해주는 도구.
1) 스페이스 신텍스 기반 공간 구조 지표를 3D로 계산
2) 가상 보행자 유동을 3D로 시뮬레이션해서 보여주기
3) 호실별 점수와 등급(S/A/B/C) 산출
4) 업종 배치안 추천과 배치안끼리 비교
5) 모든 변수를 화면에서 바꾸고 즉시 다시 계산

핵심 철학: 스페이스 신텍스는 "엔진"으로만 쓰고, 약점(수직동선, 앵커 흡인력, 배후수요, 외부 상권)은 다른 변수로 보완한다.
보정 데이터가 들어가기 전까지 이 도구는 "절대값 예측기"가 아니라 "배치안 상대 비교기"다. 화면에도 이걸 명시한다.

## 2. 기술 스택
- Vite + React + TypeScript
- 3D: three.js (@react-three/fiber, @react-three/drei)
- 상태 관리: zustand
- 무거운 계산(그래프 분석, 시뮬레이션)은 Web Worker에서 실행해서 화면이 멈추지 않게
- 차트: recharts
- 내보내기: SheetJS(xlsx), 화면 캡처 PNG
- 테스트: vitest
- 프로젝트 저장/불러오기는 JSON 파일로, 작업 중 자동저장은 localStorage (try/catch로 감싸기)
- 배포: GitHub Pages (GitHub Actions)

## 4. 공간 분석 엔진 (스페이스 신텍스)
### 4-1. 그래프 만들기
- 복도 중심선을 교차점과 꺾이는 점마다 끊어서 세그먼트로 만든다.
- 세그먼트가 노드, 서로 맞닿은 세그먼트끼리 링크로 잇는다.
- 각도 비용: 꺾이는 각도 θ에 대해 cost = θ/90 (직진이면 0, 90도면 1, 유턴이면 2).
- 호실 문 위치와 출입구는 가장 가까운 세그먼트에 붙인다.

### 4-2. 수직 연결 링크 (3D)
층과 층을 잇는 링크에 "수평 각도비용 환산값"을 매긴다. 모든 값은 settings에서 조절할 수 있어야 한다. 아래는 초기값.
- 에스컬레이터: 한 층 이동 비용 1.0
  - 방향 비대칭: 방향이 정해진 링크로 만들고, 상행 비용과 하행 비용을 따로 설정
  - 분절형(scissor): 층마다 갈아타는 이동 비용 +0.5, 갈아타는 동선이 매장 앞을 지나가도록 그 층 복도 그래프를 거치게 만들기
  - 스킵형: skippedFloors에는 연결 링크를 만들지 않기
  - voidVisible이면 비용 ×0.8 (위층이 보이면 올라갈 동기가 생기는 효과)
- 엘리베이터: 기본 비용 1.5 + 대기시간 환산(avgWaitSec × 0.02), 층수 차이에 따른 추가 비용은 작게
- 계단: 한 층 2.5, 세 층 이상은 비용이 급격히 오르게 (층수^1.5)
- 외부 데크·브릿지: 수평 세그먼트처럼 취급
- 링크마다 metricLength(m)도 함께 저장해서 metric 반경 분석이 가능하게

### 4-3. 지표 계산
- 각도 기반 최단거리(Dijkstra)로 각 노드의 다음을 구한다: 각도 총깊이 TD, 도달 노드 수 NC
- 통합도: NAIN = NC^1.2 / (TD + 2)
- 선택도: 모든 노드 쌍 최단경로가 지나가는 횟수 CH, NACH = log(CH + 1) / log(TD + 3)
- 반경: 각도 n(전체)과 metric 반경(기본 50m, 100m, 200m). 반경은 settings에서 고를 수 있게
- 출입구 깊이: 주출입구들에서 각 호실까지 최소 3D 비용
- 가시성: 호실 전면에서 복도 쪽으로 보이는 면적(간이 아이소비스트, 2D 레이캐스팅으로 근사)
- 결과는 세그먼트별, 호실별로 저장하고 3D 히트맵으로 보여준다.

## 5. 외부 요인 모듈
1단계에서는 사용자가 직접 입력하는 폼으로 만들고, 나중에 공공데이터 CSV를 불러올 수 있게 구조만 열어둔다.

```
ExternalFactors {
  residential: { bands: [{ walkMin: 5|10|15, households, avgPriceIndex(소득 대리지표), childHouseholdRatio }] }
  nearbyCommercial: [{ name, walkDistanceM, storeCount, linkStrength(0~1, 두 상권을 잇는 가로가 실제로 통과 동선인지),
                       barrier(none|대로|철도|하천|옹벽), complementarity(0~1, 업종이 보완적일수록 1),
                       directionEntranceId }]
  largeRetail: [{ name, type(대형마트|백화점|아울렛|복합몰), gfa(m2), distanceBand(근접|중거리|원거리),
                  directionEntranceId }]
  transit: [{ name, dailyRidership, walkDistanceM, directionEntranceId }]
  attractors: [{ name, type(학원가|학교|병원|공공시설|공원|업무시설), size, walkDistanceM, directionEntranceId }]
}
```

계산 방식:
- 배후세대 접근성 = Σ 세대수 × e^(−β × 보행분), β는 settings에서 조절
- 근접상권 효과 = 규모 × linkStrength × complementarity × 거리감쇠 × 단절계수(barrier마다 계수)
- 대형유통: 근접이면 +(시너지), 중거리면 −(잠식), 원거리면 0. 유형별, 연면적별 계수
- 위 값들을 합쳐서 "건물 전체 유입 지수"를 만들고, directionEntranceId를 써서 **입구별 유입 가중치**로 나눠준다. 외부 요인과 내부 3D 모형은 이 지점에서 이어진다.
- 계수는 지금은 settings의 임시 가중치를 쓰고, 화면에 "보정 전 가정값"이라고 표시한다.

## 6. 유동 시뮬레이션 (에이전트)
- 입구별 유입 가중치에 비례해서 가상 보행자를 만든다.
- 보행자마다 방문할 목적지 1~3곳을 고른다. 확률은 호실의 흡인력에 비례: (업종 기본 흡인력 × 면적^α) / 3D 비용^γ. 앵커는 흡인력이 크다.
- 3D 비용 그래프 위에서 경로를 찾되, 노이즈를 조금 섞어서 모두가 같은 길로만 가지 않게 한다.
- 지나가면서 호실 앞을 지날 때마다 통과 횟수를 쌓고, 충동 방문 확률도 조금 반영한다.
- 3D 화면에서 점이 움직이는 애니메이션으로 보여준다. 재생, 일시정지, 속도 조절, 보행자 수 조절.
- 시뮬레이션이 끝나면 세그먼트별, 호실별 누적 통행량 히트맵을 보여준다.
- 같은 seed로 돌리면 결과가 똑같이 나오게 한다. 배치안을 공정하게 비교하려면 필요하다.

## 7. 평가 모듈 (호실 점수와 등급)
- 호실 점수 = Σ wi × z(지표i)
  지표: 지역 NAIN, NACH, 출입구 깊이(값이 작을수록 좋게 부호 반전), 가시성, 시뮬레이션 통행량, 층 보정, 전면 폭
- 가중치 wi는 슬라이더로 조절하고 프리셋 몇 개를 제공한다(기본 / 보행 중심 / 앵커 중심).
- 등급: 백분위 기준 S(상위 10%), A(~35%), B(~70%), C(나머지). 기준선은 조절 가능하게.
- 임대료 가정: 기준 임대료(원/m2·월)에 등급별 배수(예: S 1.5, A 1.2, B 1.0, C 0.7)를 곱해서 호실별 예상 임대료와 총합을 보여준다.
- 보정 기능(나중 Phase): 실측 보행량이나 매출 CSV를 올리면 OLS 회귀(로그-로그)로 가중치를 추정해서 바꾸기. R2와 계수를 보여주고 VIF로 변수끼리 겹치는지 경고.

## 8. 배치 추천 모듈
업종 카테고리마다 원하는 자리 성격을 정의한다 (settings에서 수정 가능):
- 앵커(대형 F&B, 키즈, 엔터): 일부러 깊은 자리. 동선 전체를 끌어당기는 역할
- 충동형(카페, 디저트, 편의): 입구 근처, NACH가 높은 통과 동선
- 일반 리테일: 통합도가 높은 자리
- 목적형(병원, 학원, 서비스): 상층부도 괜찮음. 엘리베이터 접근성이 중요
- 업종별 목표 면적 비율(MD 구성비)을 입력받기

알고리즘:
1) 앵커 위치 후보 몇 개를 골라서 각각 시뮬레이션
2) 앵커가 정해지면 나머지 업종을 "업종 요구조건 × 호실 점수"가 최대가 되도록 배정 (탐욕 알고리즘으로 시작하고, 나중에 헝가리안이나 담금질로 개선)
3) locked 호실은 건드리지 않기
4) 결과를 배치안으로 저장해서 비교할 수 있게

## 9. 화면 구성
### 메인 페이지 (1단계 입력 = 기본 화면)
- 가운데: 3D 뷰. 층 분리 보기(층 사이를 벌려서 보기), 층 하나만 보기, 전체 보기. 회전, 줌, 이동
- 왼쪽: 입력 도구
  - 층 추가와 편집
  - 2D 평면 편집기(그리드 스냅): 호실 다각형, 복도 중심선, 출입구, 수직동선 배치
  - 기본 도형 템플릿: 직사각형 몰, ㄱ자, ㅁ자 아트리움
- 오른쪽: 변수 패널(탭으로 나누기)
  - 수직동선 비용 / 분석 반경 / 외부 요인 / 점수 가중치 / 등급 기준 / 임대료 / 시뮬레이션 설정
- 아래: 결과 패널 — 호실 등급표(정렬, 필터), 층별 등급 분포 차트, 배치안 비교
- 보기 모드 전환: 통합도 / 선택도 / 출입구 깊이 / 통행량 / 호실 등급 / 업종 배치

### "스케치업 불러오기" 버튼 (2단계 입력)
- 버튼을 누르면 불러오기 화면이 열린다.
- 스케치업 모델링 규칙을 화면에 안내한다:
  - 층별로 태그 나누기 (태그 이름 예: FL_B1, FL_1F, FL_2F)
  - 호실은 그룹으로 묶고 이름은 UNIT_호실번호
  - 복도 중심선은 CORRIDOR 태그의 선
  - 출입구는 ENTRANCE_이름 컴포넌트
  - 수직동선은 ESC_UP_이름, ESC_DN_이름, ELEV_이름, STAIR_이름 컴포넌트
- 방법 A: 스케치업 Ruby 스크립트(`tools/sketchup_export.rb`)를 같이 만든다. 스케치업에서 실행하면 위 규칙을 읽어서 이 프로그램의 Project JSON을 바로 내보내는 스크립트. 사이트에서 이 스크립트를 내려받을 수 있게 한다.
- 방법 B: DXF(층별 레이어) 불러오기. 이름 규칙은 위와 같음
- 불러온 다음에는 검증 화면을 보여준다: 연결이 끊긴 복도, 복도에 붙지 않은 호실, 수직동선이 연결되지 않은 층을 경고하고 메인 편집기에서 고칠 수 있게.

### 공통
- 상단: 프로젝트 이름, 저장/불러오기(JSON), 내보내기(xlsx 등급표, PNG 화면), 배치안 선택
- "보정 전: 상대 비교용" 배지를 항상 보이게
- 하단: "입력한 데이터는 서버로 전송되지 않습니다" 안내

## 10. 샘플 프로젝트
처음 실행하면 바로 볼 수 있는 샘플을 넣는다.
- 지하 1층(지하철 연결) + 지상 1~3층 중규모 상업시설, 층당 호실 15~25개
- 중앙 아트리움에 연속형 에스컬레이터, 한쪽 끝에 분절형 에스컬레이터, 엘리베이터 2대, 계단 2개
- 주출입구 2곳(대로변, 아파트 단지 쪽), 지하철 연결 1곳
- 외부 요인: 배후세대 5/10/15분 권역, 근접상권 1곳, 대형마트 1곳(중거리), 학원가 1곳
- 배치안 2개: (A) 앵커 3층 배치, (B) 앵커 1층 배치 → 비교 화면에서 차이가 보이게

## 11. 개발 단계 (Phase)
Phase 1 — 기본 골격과 배포
- 프로젝트 세팅, 데이터 모델, 샘플 프로젝트 불러오기, 3D 뷰(층 분리 보기), JSON 저장/불러오기
- GitHub Pages 자동 배포 설정
- 완료 기준: 샘플 건물이 3D로 보이고 층을 껐다 켤 수 있음. 공유 링크로 접속해도 똑같이 보임

Phase 2 — 공간 분석 엔진
- 세그먼트 그래프, 수직 링크(에스컬레이터 세부 규칙 포함), NAIN/NACH/깊이/가시성, 3D 히트맵, 단위 테스트
- 완료 기준: 에스컬레이터 위치를 바꾸면 상층부 히트맵이 달라지는 게 보임

Phase 3 — 평가와 변수 패널
- 점수, 등급, 임대료, 가중치 슬라이더, 등급표, 차트, xlsx 내보내기
- 완료 기준: 슬라이더를 움직이면 등급이 바로 다시 계산됨

Phase 4 — 2D 평면 편집기
- 메인 페이지에서 층, 호실, 복도, 출입구, 수직동선 그리기와 편집
- 완료 기준: 빈 프로젝트에서 직접 건물을 그려서 분석까지 돌릴 수 있음

Phase 5 — 외부 요인과 유동 시뮬레이션
- 외부 요인 폼, 입구별 유입 가중치, 에이전트 시뮬레이션 애니메이션, 통행량 히트맵
- 완료 기준: 근접상권 방향을 바꾸면 입구별 유입과 내부 통행 분포가 달라짐

Phase 6 — 배치 추천과 시나리오 비교
- 업종 요구조건, 자동 배치, locked 호실, 배치안 A/B 비교 화면
- 완료 기준: 샘플의 배치안 A와 B 차이가 숫자와 3D로 보임

Phase 7 — 스케치업 불러오기 (버튼)
- Ruby 내보내기 스크립트, DXF 불러오기, 검증 화면
- 완료 기준: 규칙대로 만든 스케치업 모델을 불러와서 분석까지 돌아감

Phase 8 — 보정과 공유 마무리
- 실측 CSV 불러오기, OLS 보정
- 사용 안내 페이지, 모바일에서도 깨지지 않는 화면, 처음 쓰는 사람용 도움말

## 12. 코드 구조 (제안)
```
src/
  model/        데이터 타입, 샘플 프로젝트, 저장/불러오기
  engine/       graph.ts(세그먼트·수직링크), syntax.ts(NAIN·NACH·깊이), visibility.ts
  external/     외부 요인 계산, 입구별 유입 가중치
  sim/          에이전트 시뮬레이션(Worker)
  scoring/      점수, 등급, 임대료, 회귀 보정
  layout/       배치 추천
  ui/           3D 뷰, 2D 편집기, 패널, 차트
  import/       스케치업 JSON, DXF
tools/sketchup_export.rb
docs/SPEC.md
.github/workflows/deploy.yml
```
